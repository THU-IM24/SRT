# 研究计划·一页版：同样的文字，不同的命运

> 2026-11-15 方向调整稿，**待导师／组会确认**；确认前立项题目与时间以[README](../../README.md)为准。[详细方案](下一步研究计划.md)。以下是设计，不是结果。旧一页版已归档：[旧一页版](archive/2026-11-08-互动结构与内容承接-一页版.md)。

**故事**：把“说了什么”（完全相同的帖子文本）或“被设定成什么样”（完全相同的简介）固定住，agent 社会里的成败还剩多少由内容决定，多少由时机、版面、作者声望、运营者和运气决定？这是机器版 Music Lab，而且是平台自己做好的野外自然实验。

| 问题 | 固定什么 | 核心交付 |
|---|---|---|
| RQ1 同样的话，不同的命运 | 帖子文本 | 同文组的点赞 ICC＋置换零分布；发布顺序与暴露时间校正；方差分解 |
| RQ2 谁造的 agent 更重要 | 简介文本 | 批量创建对独立采用家族的 ICC 对照；运营者、人设、运气的贡献 |
| RQ3（附加）agent 会改写自己吗 | 同一 agent 的快照 | 简介编辑与点赞／karma 冲击的事件研究 |

**预备证据（描述性，待复核，见[预备分析](预备分析-2026-11-15.md)）**：同文帖占 9.0%，可用组 704 个、143,101 帖，对数点赞 ICC 0.354（置换对照约 0）；同简介大组 ICC 0.707 但 46.7% 在 24 小时内创建，严格口径的独立采用家族只剩 22 组、568 个 agent，ICC 0.028。抓取累计点赞会混淆“越早越多赞”。

**底线**：只称关联，不称因果；不宣称“首次”（Music Lab 已有 LLM 版受控实验，见[文献目录](../literature/README.md)）；所有计数是抓取时的累计值；账号、正文、简介明细不进仓库。

**三周**（自 2026-11-16）：第 1 周固定口径（同文哈希、简介家族、`_scraped_at` 缺失原因）；第 2 周主分析（ICC＋置换、顺序与暴露时间校正、批量／独立）；第 3 周稳健性并决定下一步。建议分工：`huangxia` 做 RQ1，`young` 做 RQ2，`zrc` 做文献对照与 RQ3 面板核查、图表。
