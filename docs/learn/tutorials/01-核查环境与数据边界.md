## 1. 先确认终端和解释器

以下命令在服务器终端执行。教程不假定所有子账号的仓库目录相同；下面用当前核验账号的 `SRT-research` 作为示例，其他账号先把 `REPO_DIR` 改成自己的实际路径。

```bash
REPO_DIR="$HOME/SRT-research"  # 例如 SRT；按你的账号实际目录修改

```

当前约定是独立环境 `~/venv-srt`，Jupyter 内核名为 `srt`；不要再使用旧的 `/opt/miniconda/envs/srt` 或 `conda activate srt` 作为教程前提。顶层依赖见仓库根目录的 [`requirements-venv.txt`](../../../requirements-venv.txt)，完整锁文件在服务器私有目录 `~/srt-work/requirements-venv.lock.txt`，不进 Git。

若缺包，先记录 `which python`、`python --version` 和完整报错；不要用 root 安装，也不要修改公共目录权限。基础审计需要当前 venv 中的 DuckDB 和 `pytz`（DuckDB 返回 `TIMESTAMPTZ` 时使用）；PyArrow用于元数据辅助检查，图算法和Jupyter不是本页的前置条件。依赖清单已补上 `pytz`。

## 3. 先看字段，再读数据

不要先把全表加载进 pandas。激活 venv 后运行：

```bash
python - <<'PY'
import duckdb

con = duckdb.connect()
con.execute("SET TimeZone='UTC'")
con.execute("SET memory_limit='1GB'")
con.execute("SET threads=2")
con.sql("DESCRIBE SELECT * FROM read_parquet('/data/srt/outputs/posts.parquet')").show()
con.sql("DESCRIBE SELECT * FROM read_parquet('/data/srt/outputs/comments.parquet')").show()
con.sql("""
    SELECT id, author_id, created_at,
           try_cast(created_at AS TIMESTAMPTZ) AS created_utc
    FROM read_parquet('/data/srt/outputs/posts.parquet')
    LIMIT 3
""").show()
PY
```

当前使用规则：

- 主键用 `id`；账号用清洗后的 `author_id`，不要用显示名或整个 `author` 结构体建图。
- `created_at` 是 ISO 时间字符串，分析统一转换为 UTC 的 `TIMESTAMPTZ`。
- 帖子和评论的字段不能想当然地完全相同；先用 `DESCRIBE` 和小样本查询确认。
- `memory_limit` 只约束 DuckDB，不是整个 Python 进程的绝对上限；仍须观察内存、临时目录和磁盘。

## 4. 运行只读审计

审计脚本只写聚合 JSON，不导出正文或账号记录。输出目录必须在共享数据和公开仓库之外，并且每次新输入使用新目录：

```bash
REPO_DIR="$HOME/SRT-research"  # 按你的账号实际目录修改
cd "$REPO_DIR"
source ~/venv-srt/bin/activate
python src/analysis/audit_snapshot.py --help
mkdir -p ~/srt-work
python src/analysis/audit_snapshot.py \
  --out ~/srt-work/audit-$(date +%Y%m%d-%H%M%S)
```

长任务放到 tmux：

```bash
tmux new -s srt-audit
# 在 tmux 内执行上面的审计命令
# Ctrl+B，然后 D：退出但保持运行
tmux attach -t srt-audit
```

检查结果时先看 `complete`：

```bash
AUDIT_DIR=$(find "$HOME/srt-work" -mindepth 2 -maxdepth 2 -type f -name audit.json \
  -printf '%T@ %h\n' | sort -nr | cut -d' ' -f2- | head -n 1)
test -n "$AUDIT_DIR"
python -m json.tool "$AUDIT_DIR/audit.json" | less
```

`complete=false` 表示只写到了中间进度，不能当作审计完成。脚本检查主键、作者ID、时间、按月行数、帖子连接、父评论连接、原始 depth 和评论计数差异；它不识别真实操作者、不自动重建全祖先链，也不验证语义。

## 5. 怎样解释边界和异常

历史核查记录在[当前数据核查](../../notes/当前数据核查-2026-10-23.md)，其中的计数是当次服务器审计证据，不要把本页复制的旧数字当成今天重新跑出的结果。当前数据仍必须在每次正式分析的 manifest 中记录：输入路径、快照版本、时间范围、过滤规则、解释器和 DuckDB 版本。

特别注意：

1. 顶层评论的原始 `depth` 为0，且部分楼中楼也为0；不能全表无条件 `depth + 1`。
2. 找不到父评论、平台标记、计数不一致可能来自采集覆盖和平台制度，不直接等于用户行为。
3. 单一快照只能回答该快照的可观测范围，不能写成 Moltbook 全社区或长期趋势。
4. 只读审计通过，不等于网络已完整、线程已还原，也不等于已经证明存在对话。

完成后应能回答：用了哪个解释器？输入属于哪个版本？时间按什么时区？主键是否唯一？缺父节点、缺作者和标记各有多少？输出是否写到了公共数据之外？
