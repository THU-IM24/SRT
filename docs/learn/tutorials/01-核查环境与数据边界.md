# 01 核查环境与数据边界

**目标**：确认自己实际使用的解释器、快照和字段，并生成一份可复查的数据质量报告。
**先读**：[数据快照与覆盖](../concepts/数据快照与覆盖.md)、[右删失](../concepts/右删失.md)。

## 1. 明确命令在哪台电脑上运行

先用VS Code Remote-SSH进入项目服务器。以下bash命令在服务器终端执行。`~/SRT`是示例仓库目录；若你打开的是另一份克隆，请改为该克隆的目录。不要在本地数据备份中运行整理或清洗命令。

```bash
cd ~/SRT
pwd
git status --short --branch
python3 --version
python3 -c "import sys,duckdb,pyarrow; print(sys.executable); print(duckdb.__version__); print(pyarrow.__version__)"
free -h
df -h . /data/srt
```

2026-10-23核查的成员环境是Python3.12.3、DuckDB2.0.0、PyArrow26.0.0。旧文档的`/opt/miniconda/envs/srt`已不适用。不同成员账号先自行检查，不因为一个账号能import就假定所有人都已安装。

若报`ModuleNotFoundError`，把缺的包和解释器路径发给管理员。不要以root运行分析，也不要为跑教程修改公共目录权限。本教程的核心步骤只需要DuckDB；PyArrow用于辅助看Parquet元数据。NetworkX、igraph、polars当前不属于已核实可用环境。

## 2. 确认输入与输出分开

输入是：

```text
/data/srt/outputs/posts.parquet
/data/srt/outputs/comments.parquet
/data/srt/raw/moltbook-2026-10-07/parquet/agents/agents.parquet
```

前两个是合并表。原始按月Parquet与数据集说明在同一快照目录下。不要运行`src/collect/`，也不要再套用旧的JSON转换脚本。输出放自己的仓库外目录，例如`~/srt-work/`；原始数据和派生ID清单都不提交公开仓库。

## 3. 看字段，不先加载全表

在Python或Jupyter运行：

```python
from pathlib import Path
import duckdb
con = duckdb.connect()
con.execute("SET memory_limit='1GB'")
con.execute("SET threads=2")
con.execute("SET TimeZone='UTC'")
con.sql("DESCRIBE SELECT * FROM read_parquet('/data/srt/outputs/posts.parquet')").show()
con.sql("DESCRIBE SELECT * FROM read_parquet('/data/srt/outputs/comments.parquet')").show()
con.sql("""SELECT id,author_id,author.id AS nested_author,
    submolt.name AS community,try_cast(created_at AS TIMESTAMPTZ) AS created_utc
    FROM read_parquet('/data/srt/outputs/posts.parquet') LIMIT 3""").show()
```

`author`是结构体；`posts.submolt`是结构体，`comments.submolt`是字符串；`created_at`是字符串，需要转换。别把`author`本身当作可哈希账号ID。主键用`id`，账号用经检查的`author_id`。

避免`SELECT * ... .df()`读取全量：压缩文件大小远小于解压进pandas后的内存。只把最终小汇总转成DataFrame。DuckDB的memory_limit也不是整个Python进程的绝对上限，仍要观察内存和磁盘。

## 4. 跑只读审计

```bash
python3 src/analysis/audit_snapshot.py --help
tmux new -s srt-audit
python3 src/analysis/audit_snapshot.py --out ~/srt-work/audit-20261023
```

在tmux里按`Ctrl+B`再按`D`退出到后台；`tmux attach -t srt-audit`回到运行界面。运行输出每个检查名，结果持续写进指定目录的`audit.json`。不要同时启动多份全量检查。读取JSON时先看`complete`是否为true；只有中间几个字段不代表全部完成。

```bash
python3 -m json.tool ~/srt-work/audit-20261023/audit.json
```

脚本检查行数、重复ID、缺失账号、时间解析、按月行数、原始depth、帖子连接、父评论连接、实际评论数与API计数、宽松帖主出现。它不识别真实操作者、不重建所有祖先环，也不验证语义。

## 5. 怎样解释本次已知异常

2026-10-23的实测表明：帖子3,699,521条，评论19,728,495条；ID无重复，评论均能连接到已收录帖子。但存在缺父评论、缺账号ID、depth不一致和评论计数不一致。完整汇总见[当前数据核查](../../notes/当前数据核查-2026-10-23.md)。

原始顶层评论`depth=0`，概念页约定的树深是顶层1。不能无条件给全表depth加1：部分非顶层评论的depth也为0。正式树深从父关系重建。
