# 04 核对回复树与帖主回应

**版本**：2026-10-30 复核版
**目标**：区分“帖主出现”“直接回应”和“真实往返”，避免把坏父节点或窗口截断当成平坦讨论。
**先读**：[回复树](../concepts/回复树.md)、[帖主回楼](../concepts/帖主回楼.md)、[时间互惠](../concepts/时间互惠.md)。

> 02 的事件窗口适合建网络，不等于完整线程样本。本页选帖子后要从全评论表取这些帖子的评论，父节点不能随窗口一起删除。

## 1. 不直接使用原始 `depth`

当前快照顶层 `depth=0`，部分楼中楼也为0。项目约定帖子根深度0、顶层评论深度1；正式树深必须沿 `parent_id` 重建。遇到缺父、跨帖、自指、环或坏时间时，当前节点及依赖它的后代标记为不可解析，不要偷偷接到根上。

## 2. 创建受控线程样本

下面选择9月上半月创建的非平台标记帖子，再按固定 MD5 顺序取200个。它只是复现练习样本，不是总体比例的正式随机估计：

```python
from pathlib import Path
import duckdb

con = duckdb.connect()
con.execute("SET TimeZone='UTC'")
con.execute("SET memory_limit='1GB'")
con.execute("SET threads=2")
con.execute("""CREATE VIEW p AS
    SELECT id, author_id,
           try_cast(created_at AS TIMESTAMPTZ) AS ts,
           comment_count, is_spam, is_deleted
    FROM read_parquet('/data/srt/outputs/posts.parquet')
    WHERE NOT is_spam AND NOT is_deleted
""")
con.execute("""CREATE TEMP TABLE chosen AS
    SELECT * FROM p
    WHERE ts>=TIMESTAMPTZ '2026-09-01T00:00:00Z'
      AND ts<TIMESTAMPTZ '2026-09-16T00:00:00Z'
    ORDER BY md5('srt-tree-v1:' || id)
    LIMIT 200
""")
con.execute("""CREATE TEMP TABLE thread_comments AS
    SELECT c.id, c.post_id, c.parent_id, c.author_id,
           try_cast(c.created_at AS TIMESTAMPTZ) AS ts,
           c.depth, c.is_spam, c.is_deleted
    FROM read_parquet('/data/srt/outputs/comments.parquet') c
    JOIN chosen p ON c.post_id=p.id
""")
```

正式抽样要把种子、入样条件、线程规模和覆盖状态写进 manifest。先保留子节点及平台标记检查结构；排除节点时不要把它的孩子改挂到根。

## 3. 先算宽松“帖主出现”

以下查询继续在上一节创建 `con`、`chosen` 和 `thread_comments` 的同一 Python/Jupyter 会话中运行；如果分开执行，先重新创建这三个对象。

```python
con.sql("""
WITH t AS (
    SELECT p.id,
           count(c.id) AS n,
           count(c.id) FILTER (WHERE c.author_id=p.author_id) AS op_n,
           count(c.id) FILTER (WHERE c.author_id<>p.author_id) AS other_n
    FROM chosen p
    LEFT JOIN thread_comments c ON c.post_id=p.id
    GROUP BY 1
)
SELECT count(*) AS selected_posts,
       count(*) FILTER (WHERE n>0) AS commented,
       count(*) FILTER (WHERE n>0 AND op_n>0) AS op_present,
       count(*) FILTER (WHERE other_n>0) AS with_others,
       count(*) FILTER (WHERE other_n>0 AND op_n>0) AS op_present_with_others
FROM t
""").show()
```

必须同时报告分子和分母。帖主先自言自语、后来别人来评论，也会进入宽松分子；因此它不是严格回应率。

## 4. 找严格的三步往返

候选序列是 `B→A`、`A→B`、`B→A`，且三条消息在同一帖、时间严格递增：

```python
con.sql("""
SELECT count(DISTINCT b.id) AS candidate_b_a_b_sequences
FROM thread_comments b
JOIN chosen p ON b.post_id=p.id
JOIN thread_comments a
  ON a.parent_id=b.id AND a.post_id=b.post_id
JOIN thread_comments b2
  ON b2.parent_id=a.id AND b2.post_id=a.post_id
WHERE b.author_id<>p.author_id
  AND a.author_id=p.author_id
  AND b2.author_id=b.author_id
  AND b.ts<a.ts AND a.ts<b2.ts
  AND a.ts<=b.ts+INTERVAL '24 hours'
  AND b2.ts<=b.ts+INTERVAL '24 hours'
""").show()
```

这是结构候选，不证明语义承接。若只研究别人首次向帖主发问，还要限定顶层、最早互动和人工内容标签；相同时间戳应另列，不能假装知道先后。

## 5. 在单个线程重建深度

按 `post_id` 分组，用 `id → comment` 字典和“未访问／访问中／完成”状态做 DFS 或迭代遍历：帖子根深度0；父节点为空的评论深度1；其他深度为父深度+1。再次遇到“访问中”就是环；父缺失时当前节点及其后代深度未知。

不要把所有线程字典同时放进内存。按帖子迭代，并先检查单帖最大行数。当前仓库没有声称已交付全量祖先重建程序；本页是算法和受控练习规范。

## 6. 验收和分母

至少用以下合成情况手查：全顶层、A/B交替、自回复链、缺父、环。真实样本再抽查原始 depth 不一致的记录，但公开只放改写例子和聚合表。
