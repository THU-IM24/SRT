# 04 核对回复树与帖主回应

**目标**：区分帖主出现、严格回应和真实往返，并避免把坏父节点或时间窗切断当成平坦讨论。
**先读**：[回复树](../concepts/回复树.md)、[帖主回楼](../concepts/帖主回楼.md)、[时间互惠](../concepts/时间互惠.md)。

## 1. 不直接使用原始depth

当前快照顶层depth为0，部分楼中楼depth也为0。正式约定帖子深度0、顶层评论1。根据`parent_id`遍历，遇缺父、跨帖、自指、环或坏时间标为不可解析。不要简单`depth+1`后就称为重建。

选择线程时，先按帖子创建时间选一个批次，再从全评论表取这些帖子的全部可观察评论。02的`events.parquet`按评论发生时间选取，只适合窗口事件网络，不能当成完整线程集合。

## 2. 创建一份受控线程样本

下面从9月上半月的新帖中按ID的MD5顺序选200个线程。它是复现练习样本，不是总体比例的正式随机估计。SQL中的时间均为UTC。

```python
from pathlib import Path
import duckdb
con=duckdb.connect()
con.execute("SET memory_limit='1GB'")
con.execute("SET threads=2")
con.execute("SET TimeZone='UTC'")
con.execute("""CREATE VIEW p AS SELECT id,author_id,try_cast(created_at AS TIMESTAMPTZ) AS ts,
 comment_count FROM read_parquet('/data/srt/outputs/posts.parquet')
 WHERE NOT is_spam AND NOT is_deleted""")
con.execute("""CREATE TEMP TABLE chosen AS SELECT * FROM p
 WHERE ts>=TIMESTAMPTZ '2026-09-01T00:00:00Z'
 AND ts<TIMESTAMPTZ '2026-09-16T00:00:00Z'
 ORDER BY md5('srt-tree-v1:'||id) LIMIT 200""")
con.execute("""CREATE TEMP TABLE thread_comments AS
 SELECT c.id,c.post_id,c.parent_id,c.author_id,
 try_cast(c.created_at AS TIMESTAMPTZ) AS ts,c.depth,c.is_spam,c.is_deleted
 FROM read_parquet('/data/srt/outputs/comments.parquet') c JOIN chosen p ON c.post_id=p.id""")
```

先保留所有子节点及标记以检查结构。若后来排除spam节点，不要把它的孩子偷偷移到根上；可以将整条路径标为穿过被排除节点。

## 3. 先算宽松“帖主出现”

```python
con.sql("""WITH t AS (
 SELECT p.id,count(c.id) AS n,
 count(c.id) FILTER(WHERE c.author_id=p.author_id) AS op_n,
 count(c.id) FILTER(WHERE c.author_id<>p.author_id) AS other_n
 FROM chosen p LEFT JOIN thread_comments c ON c.post_id=p.id GROUP BY 1)
SELECT count(*) AS selected_posts,
 count(*) FILTER(WHERE n>0) AS commented,
 count(*) FILTER(WHERE n>0 AND op_n>0) AS op_present,
 count(*) FILTER(WHERE other_n>0) AS with_others,
 count(*) FILTER(WHERE other_n>0 AND op_n>0) AS op_present_with_others FROM t""").show()
```

分子除以哪个分母要在结果旁写明。帖主先自言自语、后来别人来评论，也会进入这个宽松分子；所以它不是回应率。

## 4. 找严格的三步往返

```python
con.sql("""SELECT count(DISTINCT b.id) AS candidate_B_A_B_sequences
 FROM thread_comments b
 JOIN chosen p ON b.post_id=p.id
 JOIN thread_comments a ON a.parent_id=b.id AND a.post_id=b.post_id
 JOIN thread_comments b2 ON b2.parent_id=a.id AND b2.post_id=a.post_id
 WHERE b.author_id<>p.author_id AND a.author_id=p.author_id
 AND b2.author_id=b.author_id AND b.ts<a.ts AND a.ts<b2.ts
 AND a.ts<=b.ts+INTERVAL '24 hours'
 AND b2.ts<=b.ts+INTERVAL '24 hours'""").show()
```

这里的候选B可以是任意非帖主评论。若只研究别人首次向帖主发问，要进一步限定顶层、最早互动及人工内容标签。时间戳相同时另列，不假装知道先后。上式只查结构，不证明语义承接。

## 5. 在单个线程重建深度

用字典`id→评论`和状态`未访问/访问中/完成`做DFS或迭代遍历。帖子根深度为0；父节点为空的评论深度1；其他深度为父深度+1。再次遇“访问中”是环。父节点缺失时当前节点与依赖它的后代都记未知。深度统计同时报告可重建线程占比。

不要把所有线程的字典同时加载。按选中post_id分组迭代，并检查最大单帖行数。如果一个线程异常庞大，先按规模分层处理。

## 6. 验收

手查至少5种合成情况：全顶层、A/B交替、自回复链、缺父、环。再查真实样本中原始depth不一致的若干私有记录。公开只放改写例子与聚合表。严格率的分母还要满足固定后随访窗口，接着读[05 时序与删失](05-按时间窗比较对话持续.md)。
