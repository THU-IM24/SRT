# 05 按时间窗比较对话持续

**版本**：2026-10-30 复核版
**目标**：把“有没有回应”和“回应有多快”分开，建立有资格、可比较的回应机会表。
**先读**：[右删失](../concepts/右删失.md)、[时间衰减](../concepts/时间衰减.md)、[生存分析](../concepts/生存分析.md)。

## 1. 先写估计对象

一个清楚的主问题可以是：在父关系可靠、创建后至少观察24小时的非帖主评论中，帖主在24小时内直接回复的比例是多少？另报有回复者的等待时间分位数。

- 单位是“候选评论”，不是帖子、账号或所有有向边。
- `replied_24h` 的分母必须包含完整24小时观察机会。
- “有回复者的等待时间中位数”不能写成全部评论的回应能力。
- 若研究7天跨帖再接触，另建账号对或账号—线程表，不共用这个分母。

## 2. 明确观察截点

评论最大创建时间只能提供数据边界线索，不能证明此前每条评论都完整。先做01审计，再把本次分析的 `cutoff_utc` 明确写进 manifest；不要把历史示例日期复制成永久配置。

若 `cutoff_utc` 是正式截点：

- 24小时候选：`parent_ts < cutoff_utc - 24 hours`；
- 7天候选：`parent_ts < cutoff_utc - 7 days`；
- 所有回应必须满足 `reply_ts <= cutoff_utc`。

至少做提前1天、提前7天的截点敏感性。数据集存在回填、捕获延迟和回复深度限制时，随访完整也不等于行为完全可见。

## 3. 构造首次目标回复时间

沿04得到的父子表，取候选评论之后最早、作者符合目标条件的直接子回复：

```sql
SET TimeZone='UTC';

SELECT parent.id,
       min(child.ts) FILTER (WHERE child.ts>parent.ts) AS first_reply
FROM candidates AS parent
LEFT JOIN all_thread_comments AS child
  ON child.parent_id=parent.id
 AND child.post_id=parent.post_id
 AND child.author_id=parent.post_author_id
GROUP BY parent.id;
```

这是设计 SQL，不是可直接运行的成品：`candidates`、`all_thread_comments` 和 `post_author_id` 必须先按项目规则创建。研究“任何人回复”时另写条件并改名，不能把它和帖主回复混称。

## 4. 固定随访基线

至少输出：`eligible_24h`、`replied_24h`、`replied_24h / eligible_24h`、`wait_seconds` 的 p25/中位数/p75、父关系不可解析率和覆盖排除数。

无回复但有完整24小时观察的候选记 `replied_24h=0`；随访不足、父关系不可解析或时间异常记为不合格，不是0。可按月份、线程规模、平台标记、社区和账号活动层分层，但小样本层只作描述。

## 5. 生存分析保留未回复者

若要保留不同随访时长，构造：

```text
duration = min(first_reply_ts, cutoff_utc) - parent_ts
event = 1 if 在 cutoff 前观察到目标回复，否则 0
```

Kaplan–Meier 或其他生存模型只有在删失机制和覆盖边界足够可解释时才可这样解释。中位数没有达到时写“未达到”，不能用已回复样本的中位数替代。当前仓库尚未交付正式生存分析脚本；先在人工核对的候选表上验证。

## 6. 长期比较要控制构成

不要把1月所有新账号与9月仍活跃账号直接比成“学习进步”。至少同时看固定月批次、固定活跃账号面板和新进入账号，并报告前期活动、语言、社区、线程规模和随访差异。失活、选择进入、采集制度变化仍可能造成偏差。

制度前后比较需要真实发布时间、采用日志和可辩护的对照；当前快照的观察性差异不能自动变成因果效应。

## 7. 最低交付

交一张含资格分母、回应比例、条件等待分位数、不可解析率和截点敏感性的表；另附数据覆盖声明和 manifest。对话持续已有直接论文，当前项目是否有增量要回到[下一步研究计划](../../notes/下一步研究计划.md)判断。
