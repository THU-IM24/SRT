## 3. 计算每个账号的度与强度

下面的 `node_stats` 只包含至少参与一条有效边的端点：

```python
# 如果上一段是在单独的终端命令中运行，先在当前 Python/Jupyter 会话重新建立 con：
from pathlib import Path
import duckdb

edge_file = Path.home() / 'srt-work' / '本次输出目录' / 'main_edges.parquet'
con = duckdb.connect()
con.execute("SET memory_limit='1GB'")
con.execute("SET threads=2")
con.read_parquet(str(edge_file)).create_view('e')

con.execute("""CREATE TEMP TABLE node_stats AS
WITH incoming AS (
    SELECT dst AS id, count(*) AS kin, sum(weight) AS sin
    FROM e GROUP BY 1
), outgoing AS (
    SELECT src AS id, count(*) AS kout, sum(weight) AS sout
    FROM e GROUP BY 1
), nodes AS (
    SELECT src AS id FROM e UNION SELECT dst FROM e
)
SELECT n.id,
       coalesce(kin, 0) AS kin, coalesce(kout, 0) AS kout,
       coalesce(sin, 0) AS sin, coalesce(sout, 0) AS sout
FROM nodes n
LEFT JOIN incoming i USING (id)
LEFT JOIN outgoing o USING (id)
""")
con.sql("""
    SELECT count(*) AS nodes,
           sum(kin) AS indegrees, sum(kout) AS outdegrees,
           sum(sin) AS instrength, sum(sout) AS outstrength
    FROM node_stats
""").show()
```

核对恒等式：入度与出度总和都应等于二值边数；入强度与出强度总和都应等于事件权重。它们不相等时先查重复边、空ID、权重类型和连接逻辑，不要直接解释结果。

报告节点全集时写清“有效边端点”，因为它不包括从未出现在有效评论边中的发帖账号。CCDF先输出频数表；不要先把尾部画成直线就宣称幂律。

## 4. 计算静态边互惠

```python
con.sql("""
SELECT count(*) AS directed_edges,
       count(*) FILTER (WHERE b.src IS NOT NULL) AS reciprocated_edges,
       count(*) FILTER (WHERE b.src IS NOT NULL) * 1.0
           / nullif(count(*), 0) AS edge_reciprocity
FROM e a
LEFT JOIN e b ON a.src=b.dst AND a.dst=b.src
""").show()
```

每个双向账号对贡献两条互惠有向边。对 `reply_edges.parquet` 另建 view，再用同一公式；不要把主网络与直接回复网络的互惠混成一个指标。静态互惠只说明边方向上存在反向边，不等于语义承接、及时回应或持续对话。

## 5. 计算非负量的 Gini

以下是“边端点账号的入强度不均”，不是 karma 不均：

```python
con.sql("""
WITH ranked AS (
    SELECT sin AS x,
           row_number() OVER (ORDER BY sin, id) AS r,
           count(*) OVER () AS n
    FROM node_stats
)
SELECT CASE WHEN sum(x)>0 THEN
    2.0*sum(r*x)/(max(n)*sum(x))-(max(n)+1.0)/max(n)
END AS gini_in_strength
FROM ranked
""").show()
```

同时报告零入强度比例和头部占比。普通 Gini 不适合含负数的 karma；不要把不同节点全集或不同分母的 Gini 直接横比。

## 6. 图算法与零模型是后续步骤

当前 venv列出了 NetworkX、igraph 等依赖，但大图仍须受控：先报告 N/E 和边类型，再做分量、聚类和 k-core；路径只在 LSCC 或抽样源节点上算，不生成全对最短路径矩阵。无向投影算 k-core 时要写清方向信息丢失。

随机基线写清保留什么：度序列、密度、时间机会，还是其他约束。不要只交一张网络图，也不要把“能画出来”当作结构已验证。
