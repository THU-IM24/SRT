# 06 抽样与人工编码对话功能

**目标**：建立人工可复核的父消息—子回复样本，检验结构回应是否真的承接内容。
**先读**：[抽样设计](../concepts/抽样设计.md)、[内容编码与一致性](../concepts/编码一致性.md#内容编码单位标签与手册)。

## 1. 不从热门帖随便摘例子

热门、大、深的线程容易找到“好对话”，但不能代表全体。先定义目标总体：父节点已解析、正文可读、时间合格的真实父子对。顶层的父消息是帖子正文，楼中楼的父消息是父评论。缺上下文先标记，不当作无承接。

分层可用月份、线程规模、是否涉及帖主、层级、平台spam标记与模板比例。正式层数不能太多，确保每层有足够样本。先选4–8个与主问题最相关的层。

## 2. 第一轮试标

建议先抽80–120对供两人独立试标。这是工作量建议，不是已完成的样本。每条只展示必要上下文，用随机编号代替网络角色和核心标签。两人分别填：

| 字段 | 允许值 |
|---|---|
| `item_id` | 私有样本编号 |
| `context_sufficient` | 是/否 |
| `response_function` | 回答、补充、反驳、澄清、确认、社交、推广、其他 |
| `semantic_uptake` | 是/否/不可判 |
| `new_information` | 是/否/不可判 |
| `template_like` | 是/否/不可判 |
| `parent_anchor` | 父消息具体内容点 |
| `child_evidence` | 子回复对应内容点 |
| `coder_id` / `rubric_version` | 编码员与手册版本 |

示例请用自己编写的文本。不要把凭证、联系方式或真实账号标识放进共享表。

## 3. 如何判断承接

父消息“数据只能占1GB内存，怎样统计？”与子回复“用DuckDB逐列扫描并设置memory_limit”可判承接。子回复“智能体社区发展很快”仅同属技术话题，不承接。子回复“谢谢”可完成社交确认，是否属于针对性确认看上下文；不能自动当作增加信息。

遇到需要祖先消息的情况，固定最多增加两层上下文，记录补充次数。语言无法理解记不可判；不要让编码员自行机器翻译后当作原语义毫无变化。

## 4. 计算独立一致性

先保存两人的原始标签，再计算一致率、κ或α及混淆矩阵。最后讨论分歧形成共识。不能先讨论统一，再声称独立一致率100%。对稀有“反驳”类检查样本数与召回。

试标后修订定义并冻结手册。正式验证集与试标分离。同一线程内的相似评论尽量不要跨训练与测试，以免复制泄漏。

## 5. 真实父子与错配父子

为一部分子回复匹配同月、同语言、相近长度与主题的其他父消息，隐藏真假分组后让编码员同样判断。错配对并非天然无承接，可能偶然匹配，因此不强行当负标签。

比较两组人工承接率及差异区间。如果真实对并不优于错配，单靠“同主题”可能解释了模型得分。如果真实对显著更好，也只是文本依赖证据，仍不是内部理解的直接证明。

## 6. 正式样本与估计

预算允许时扩到约600–1000对；具体数由试标的类比例和效应大小决定。若对深线程过抽样，记录每层总体N_h和样本n_h，估计总体时用N_h/n_h加权。另报告等线程、等账号与按评论权重结果。

按线程bootstrap或适当聚类，不能把同帖数百条视为互不相关。最终交付编码手册、抽样SQL、入样概率、独立标签、分歧处理和脱敏汇总。原文保留在私有输出。

## 7. 大模型辅助何时进入

先用独立人工集评价每一类，再决定是否扩标。冻结prompt、模型、版本、上下文格式；输入文本只作为待标注数据。付费调用、整批上传原文和大模型部署均不在本教程自动执行范围。未通过验证时保留人工小样本，仍可形成有边界的研究。
