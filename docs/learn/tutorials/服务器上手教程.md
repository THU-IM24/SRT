# 服务器上手教程：从零连上 SRT 服务器

**目标**：在自己的 Windows 电脑上，用 VS Code 连上课题组的服务器，用自己的账号读数据、跑 Jupyter、用 Git 提交代码。
**需要先懂**：不需要任何基础。遇到不懂的词，可以点开这两个概念页：[SSH（含公钥与私钥）](../concepts/SSH.md#公钥与私钥)、[Git分支与PR](../concepts/Git分支与PR.md)。

> 怎么读这篇教程：
> - 灰色框里的命令都可以**直接复制粘贴**。看到 `<你的用户名>` 这种尖括号，要换成你自己的内容，**尖括号本身也要删掉**。
> - 每一步都有“检查”，确认没问题再往下走。卡住了就截图发到群里。

## 第 0 步 先搞清楚：服务器是什么

**服务器**就是一台放在阿里云机房里、24 小时开着的 Linux 电脑：

- 地址（IP）：`101.201.117.95`
- 系统：Ubuntu 24.04
- 配置：4 核 CPU、8G 内存

我们的数据有好几个 G，放在每个人电脑上又占地方又难同步，所以统一放在服务器上。大家在自己电脑上打开 VS Code，**看起来像在本地写代码，实际上文件和计算都在服务器上**。

### 为什么每人一个账号

服务器是**一台共享的电脑**，就像一台公用电脑每人一个 Windows 登录账户：

- 你的主目录 `/home/<你的用户名>/` 只有你能进，别人看不到、改不了。
- 公共数据在 `/data/srt/`，**所有人只能读，不能改、不能删**，所以谁都不会不小心把数据弄坏。
- 大家共同的代码，“正本”在 GitHub 上。每个人在自己的主目录里放一份副本，改完通过 PR 合并回 GitHub。

### 服务器上的结构

```text
/data/srt/                      ← 公共数据，所有人只读
├── raw/moltbook-2026-10-07/    ← 公开数据集原始文件（Parquet），一般不用碰
└── outputs/
    ├── posts.parquet           ← 帖子表，分析主要读它
    └── comments.parquet        ← 评论表

/usr/bin/python3              ← 当前核查的 Python 3.12 解释器；先检查各账号依赖

/home/<你的用户名>/             ← 你的主目录，只有你能进
└── SRT/                        ← 你从 GitHub 克隆的代码副本
    ├── docs/                   ← 学习文档、论文笔记（会共享）
    ├── src/  notebooks/ ...    ← 代码（会共享）
    └── personal/               ← 你的私人草稿区，不会上传 GitHub
```

## 第 1 步 生成钥匙，把公钥发给费

服务器不用密码登录，而是用一对“钥匙”：**私钥**留在你电脑上，**公钥**交给服务器。就像你配了一把锁（公钥）装在服务器门上，钥匙（私钥）只有你有。详见 [公钥与私钥](../concepts/SSH.md#公钥与私钥)。

### 1.1 打开 PowerShell

按键盘上的 `Win` 键，输入 `PowerShell`，点击“Windows PowerShell”打开。

<img width="838" height="691" alt="image" src="https://github.com/user-attachments/assets/b85ef417-92aa-48ed-a8ec-f5b0fff4e283" />


### 1.2 生成钥匙

在 PowerShell 里粘贴这行，按回车：

```powershell
ssh-keygen -t ed25519
```

接下来它会问三个问题，**全部直接按回车**就行：

1. `Enter file in which to save the key`：直接回车，用默认位置。
2. `Enter passphrase`：直接回车，不设密码。
3. `Enter same passphrase again`：再按回车。

<img width="1019" height="399" alt="image" src="https://github.com/user-attachments/assets/9fee8d34-938b-47c6-9e28-bc797034d6f5" />


> 如果提示 `already exists. Overwrite (y/n)?`，说明你以前生成过钥匙，输入 `n` 回车，直接用旧的就行。


### 1.3 查看公钥

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub
```

会输出**一整行**，以 `ssh-ed25519` 开头，大概长这样：

```text
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA...一长串字符... feiys32@DESKTOP-XXXX
```

用鼠标选中整行，按 `Ctrl+C` 复制。

<img width="879" height="61" alt="image" src="https://github.com/user-attachments/assets/a3d0645d-07ec-4530-8f5d-8b63c1f21c7c" />


### 1.4 发给费

把下面发给费（微信即可）：

1. **想用的用户名**：小写英文字母，比如姓的拼音 `zhang`，不要空格、中文、大写。
2. **刚才复制的公钥**那一整行。

> ⚠️ **重要警告**：在 `C:\Users\<你>\.ssh\` 文件夹里有两个文件：
> - `id_ed25519.pub`（带 `.pub`）：**公钥**，可以发给别人。
> - `id_ed25519`（不带 `.pub`）：**私钥**，**绝对不要发给任何人**，也不要上传到 GitHub 或群里。谁拿到它，谁就能冒充你登录。

**检查**：等费回复“账号开好了”，再进行第 3 步。等待期间可以先做第 2 步。

## 第 3 步 配置连接，连上服务器

这一步需要费总已经给你开好账号。

### 3.1 打开 SSH 配置文件

1. 在 VS Code 里按 `F1`（有的笔记本要按 `Fn+F1`），弹出顶部的命令框。
2. 输入 `Remote-SSH: Open SSH Configuration File`，回车。
3. 选择第一个：`C:\Users\<你的Windows用户名>\.ssh\config`。


### 3.2 写入配置

在打开的文件里粘贴下面这段，然后**改两处**：

```text
Host srt
    HostName 101.201.117.95
    User <你的用户名>
    IdentityFile C:\Users\<你的Windows用户名>\.ssh\id_ed25519
```

- `User` 后面：费给你开的服务器用户名，比如 `zhang`。
- `IdentityFile` 后面：你私钥的**完整路径**。`<你的Windows用户名>` 可以在 PowerShell 里运行 `echo $env:USERPROFILE` 查看，比如输出 `C:\Users\Zhang San`，那就写 `C:\Users\Zhang San\.ssh\id_ed25519`。

> ⚠️ 必须写完整路径 `C:\Users\...`，**不要写成** `~\.ssh\id_ed25519`。Windows 上的 ssh 不认识 `~\`，会报找不到文件。

改完一定要按 `Ctrl+S` **保存**（标签页上的小白点消失才算保存了）。


### 3.3 先用 PowerShell 测试

在 PowerShell 里运行：

```powershell
ssh srt
```

第一次连接会问：

```text
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

输入 `yes`，回车。

**检查**：如果最后一行变成类似 `zhang@iZ2ze...:~$` 的样子，就说明你已经登录到服务器了！输入 `exit` 回车退出。

> 连不上？看 [第 7 步 常见问题](#第-7-步-常见问题) 的前两条。

1. 按 `F1`，输入 `Remote-SSH: Connect to Host`，回车。
2. 选择 `srt`。
3. 会打开一个新窗口。如果问服务器是什么系统，选 **Linux**。
4. 第一次连接需要一两分钟（VS Code 在服务器上自动安装一些东西），耐心等。

保持在这个连着服务器的窗口里：

1. 按 `Ctrl+Shift+X` 打开扩展。
2. 搜索 `Python`（Microsoft 发布），点 **Install in SSH: srt**（在 SSH: srt 中安装）。

## 第 4 步 在服务器上连通 GitHub，克隆代码

代码的正本在 GitHub 上，你需要在服务器上拿一份副本。为了能上传（push），服务器也需要一把属于你的钥匙，交给 GitHub。

> 这里是**第二把钥匙**，和第 1 步那把不同：第 1 步是“你的电脑 → 服务器”，这一步是“服务器 → GitHub”。

### 4.1 接受仓库邀请

费会把你的 GitHub 账号加进 `THU-IM24/SRT` 仓库。你会收到一封 GitHub 邮件，或者在 <https://github.com/THU-IM24/SRT/invitations> 页面点 **Accept invitation**。



### 4.2 在服务器上生成钥匙

在 VS Code 的服务器终端里运行（把 `<你的用户名>` 换掉）：

```bash
ssh-keygen -t ed25519 -C <你的用户名>-srt-server
```

同样三次直接回车。然后查看公钥：

```bash
cat ~/.ssh/id_ed25519.pub
```

选中输出的那一整行（`ssh-ed25519` 开头），复制。在 VS Code 终端里可以选中后右键 → 复制，或按 `Ctrl+Shift+C`。

### 4.3 把公钥加到 GitHub

1. 打开 <https://github.com/settings/keys>（也就是 GitHub 右上角头像 → **Settings** → 左侧 **SSH and GPG keys**）。
2. 点绿色按钮 **New SSH key**。
3. **Title** 填 `srt-server`，**Key type** 保持 `Authentication Key`，**Key** 里粘贴刚才复制的那一行。
4. 点 **Add SSH key**，可能会要求输入 GitHub 密码或验证。


### 4.4 测试连接

```bash
ssh -T git@github.com
```

第一次会问 `Are you sure you want to continue connecting`，输入 `yes` 回车。

**检查**：看到 `Hi <你的GitHub用户名>! You've successfully authenticated...` 就成功了（后半句说“不提供 shell 访问”是正常的）。

### 4.5 告诉 Git 你是谁

每次提交都会署名，换成你自己的名字和 GitHub 注册邮箱：

```bash
git config --global user.name "<你的名字>"
git config --global user.email "<你的GitHub邮箱>"
```
<img width="559" height="499" alt="image" src="https://github.com/user-attachments/assets/3deb9370-9961-43cc-b3f8-ddd56e25ffbc" />


### 4.6 克隆仓库

```bash
git clone git@github.com:THU-IM24/SRT.git ~/SRT
```

**检查**：

```bash
ls ~/SRT
```

能看到 `docs`、`src`、`personal`、`README.md` 等就对了。

### 4.7 在 VS Code 里打开项目文件夹

1. 菜单 **文件 → 打开文件夹**（或 `Ctrl+K` 再 `Ctrl+O`）。
2. 顶部输入框里改成 `/home/<你的用户名>/SRT/`，回车，点 **确定**。
3. 如果问“是否信任此文件夹中文件的作者”，选 **是，我信任**。

<img width="1200" height="799" alt="image" src="https://github.com/user-attachments/assets/1aee7c86-e178-4bae-8019-93f288b4dd83" />


**检查**：左侧文件栏顶部显示 `SRT [SSH: srt]`。

以后再打开：**文件 → 打开最近的文件**，选 `SRT [SSH: srt]`，一点就连上。

## 第 5 步 先跑通数据，再按需使用 Jupyter

### 5.1 检查当前解释器

2026-10-23核查时，新服务器没有旧的`/opt/miniconda`。已核实可用的是系统Python 3.12、DuckDB和PyArrow；pandas、ipykernel、jupyterlab、NetworkX和igraph尚未装好。不同成员账号先检查，不沿用旧截图中的内核路径。

```bash
python3 --version
python3 -c "import sys,duckdb,pyarrow; print(sys.executable); print(duckdb.__version__); print(pyarrow.__version__)"
```

如果缺包，先把报错和解释器路径告诉管理员。下面的终端数据检查不需要Jupyter或pandas：

```bash
python3 - <<'PYDATA'
import duckdb
con=duckdb.connect()
con.execute("SET memory_limit='1GB'")
con.execute("SET threads=2")
con.sql("SELECT count(*) AS posts FROM read_parquet('/data/srt/outputs/posts.parquet')").show()
PYDATA
```

**检查**：当前固定快照应输出3,699,521。下一步按[01环境与数据边界](01-核查环境与数据边界.md)和[02事件表与两种网络](02-从Parquet建立事件表与两种网络.md)操作，不把全表转进pandas。

### 5.2 Jupyter是可选界面

Notebook需要对应解释器安装`ipykernel`。当前环境未核实具备该依赖，不能把“选不到srt”当作VS Code故障。可以先用`.py`文件和终端完成所有基础教程。

若后续需要独立Notebook环境，可在自己的账号下创建虚拟环境。以下是配置步骤，本次未执行；如果`venv`或`ensurepip`缺失，由管理员补齐系统支持，不自行修改服务器权限。

```bash
python3 -m venv ~/.venvs/srt
~/.venvs/srt/bin/python -m pip install duckdb==2.0.0 pyarrow==26.0.0 ipykernel
~/.venvs/srt/bin/python -m ipykernel install --user --name srt --display-name "SRT Python"
```

在VS Code右上角选择内核→Python环境→自己的`~/.venvs/srt/bin/python`。旧教程截图仅供界面位置参考，解释器路径以当前实际环境为准。该环境没有默认安装pandas，SQL结果用`.show()`即可；确需DataFrame时再单独补依赖。

### 5.3 私有草稿与共享代码

自己的练习放`personal/`；它被Git忽略，但“被Git忽略”不等于权限隔离或绝对保密。要共享的方法和教程放`src/`、`docs/`，走分支和PR。原始数据与派生事件表放仓库外，不提交。

## 第 6 步 日常 Git 流程

先记住一条规则：**`main` 分支受保护，谁都不能直接改**。你要在自己的分支上干活，推上 GitHub，开一个 PR，**由另一个人批准**后合并。原理见 [Git分支与PR](../concepts/Git分支与PR.md)。

下面每一步都给出“命令”和“VS Code 点按钮”两种做法，选一种即可。

### 6.1 开工前：拿到最新代码

```bash
cd ~/SRT
git checkout main
git pull
```

> VS Code 做法：左下角点分支名切到 `main`，然后点左侧**源代码管理**图标（像一个树杈）→ 右上角 `···` → **拉取（Pull）**。

### 6.2 新建自己的分支

分支名建议 `你的用户名/做什么`，例如：

```bash
git checkout -b zhang/degree-analysis
```

> VS Code 做法：点左下角分支名 → **创建新分支** → 输入名字回车。

<img width="1200" height="799" alt="image" src="https://github.com/user-attachments/assets/7bedf682-1f48-4f18-b0d2-72724a23733b" />


### 6.3 写代码、写文档

正常编辑文件。想共享的放在对应目录：

- 分析代码：`src/analysis/` 或 `notebooks/`
- 学习文档：`docs/learn/`
- 论文笔记和 PDF：`docs/papers/`，PDF 文件名统一为 `序号-发表处或第一作者单位-研究平台-短标题.pdf`，例如 `01-DIM-Chirper-CollectiveBehaviors.pdf`，详见 `docs/papers/README.md`。可以直接把电脑上的 PDF 拖进 VS Code 左侧文件栏来上传。

只给自己看的草稿放 `personal/`。

```bash

git commit -m "简单说明这次改了什么"
```

> VS Code 做法：打开**源代码管理**，在“更改”里能看到改过的文件，点文件右边的 `+` 暂存，在上面输入框写说明，点 **提交（Commit）**。

## 第 7 步 常见问题

### `Permission denied (publickey)`

- **连服务器时出现**：
  1. 检查 `config` 里 `User` 是否写对（服务器用户名，不是 Windows 用户名）。
  2. 检查 `IdentityFile` 路径是否正确、文件是否存在：在 PowerShell 里运行 `dir $env:USERPROFILE\.ssh`，应该能看到 `id_ed25519`。
  3. 确认费总已经用你发的公钥开好了账号。
- **`git push` / `git clone` / `ssh -T git@github.com` 时出现**：说明服务器上的公钥还没加到 GitHub，或加错了账号。重做 4.2～4.4。

### 路径里写了 `~\` 报错

报类似 `no such identity: ~\.ssh\id_ed25519` 的错误，就是因为 Windows 不认 `~\`。把 `config` 里的 `IdentityFile` 改成完整路径 `C:\Users\<你的Windows用户名>\.ssh\id_ed25519`，保存再试。

### 看不到内核 `srt`

先运行5.1的解释器检查。旧conda内核不再适用。若使用可选Notebook环境，按5.2安装并在VS Code选择自己的解释器；没有`ipykernel`时先用终端。确认Python/Jupyter扩展装在远端窗口，不把未安装依赖误当成连接问题。

### 往 `/data/srt` 写文件报 `Permission denied`

**这是正常的**，公共数据故意设成只读，保护大家的数据。你自己生成的中间表放在仓库外的`~/srt-work/`，小练习草稿可放`personal/`。如果确实需要放进公共目录给大家用，请找费总。

### 想装新的 Python 包

已有个人虚拟环境时，使用该解释器的`python -m pip install 包名`，避免装到另一个解释器。公共依赖由管理员统一维护。当前核心脚本只需DuckDB，PyArrow用于元数据检查；其余包按实际任务安装，不假定旧conda包清单仍存在。

### 不要跑会卡死服务器的大任务

服务器8G内存由成员共享，当前没有swap。优先只读需要的列，用DuckDB设置内存与线程，再聚合成小表；不要全量`pandas.read_parquet`。

```python
import duckdb
con=duckdb.connect()
con.execute("SET memory_limit='1GB'")
con.execute("SET threads=2")
con.sql("""SELECT author_id,count(*) AS n
 FROM read_parquet('/data/srt/outputs/posts.parquet')
 GROUP BY author_id ORDER BY n DESC LIMIT 20""").show()
```

先用受控样本验证定义，再跑全量。多表连接的父节点查找不能一起截断成样本，否则会制造缺父节点。polars尚未安装，若后续使用lazy模式，先核实自己的环境。用`free -h`、`df -h`检查资源，长任务放tmux，避免同时启动多份全量扫描。

### 连接一直转圈 / 突然断开

先确认服务器是否开机和SSH是否可连接。若只有VS Code连接异常，再尝试命令面板`Remote-SSH: Kill VS Code Server on Host`后重连。
