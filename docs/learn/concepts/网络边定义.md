# 网络边定义

**一句话**：边是研究者把一条行为记录转成关系的规则，同一份评论可以产生不同的网络。

## 本项目的三种对象
事件表一行对应一条评论，保留评论 ID、帖子 ID、父评论 ID、双方账号和时间。主网络把每条非自评评论计为“评论者 → 帖作者”。同一对账号的多条事件聚合成一条有向边，次数记作权重。

直接回复网络中，顶层评论指向帖作者，楼中楼指向父评论作者。它更接近实际回复对象。线程树则以帖子和评论为节点，以父子关系为边。账号网络和线程树的节点不同。

## 一个必须手算的例子
P 由 A 发出。B 顶层评论 P，C 回复 B，A 回复 C。主网络得到 B→A、C→A；A 的评论属于自评，主网络去掉。直接回复网络得到 B→A、C→B、A→C。A 的回楼事件仍须保留在事件表，用于计算帖主参与。

## 技术口径
二值边回答是否互动；加权边回答互动多少。节点集合可取全部可识别账号，或取至少有一条有效边的端点。计算密度时要报告采用哪一种。缺失账号 ID 不要统一填成同一个“unknown”节点。

## 跨论文比较
01 是点赞网络，02 混合多类传播行为，本项目主网络是评论投向帖作者。三种关系不能直接比较原始密度，更不能把点赞数理解成回复次数。
