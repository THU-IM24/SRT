# 回复树

回复树以帖子为根，以评论为其余节点，用父消息到子回复的边保存讨论的嵌套结构。它回答评论接在哪条消息下面，以及讨论有多深、多宽。本研究先重建回复树，再定位帖主直接回应和B、A、B三步往返。树深只表示结构，不能替代作者轮换或语义承接。

## 深度、宽度与规模

本项目固定帖子深度为0，顶层评论深度为1。最大深度d是从帖子到最深评论的边数；宽度w是评论最多一层的评论数；规模n是评论总数，不含帖子。

P下面有c1、c2，c1下面还有c3时，n=3、d=2、w=2。没有评论时约定n=d=w=0，但不把这种帖子放进“有评论线程”的比例分母。

当前数据原始`depth=0`表示顶层评论，与上述约定差1；部分原始值还不符合父子关系。不能仅把原字段加1就称为重建。

## 从字段重建时先检查关系

1. 用`post_id`找到帖子。父ID为空才接到帖子；非空则查找父评论。
2. 核对父评论存在、同帖、不是当前评论自己，并且时间早于子评论。相同时刻单列为先后未知。
3. 检查父链能否到达根，是否有环。缺父或坏链的节点及依赖它的后代记不可解析，不自动移到根上。

先按帖子批次选线程，再从全评论输入取这些帖的全部可观察评论。按评论时间先截出一个月，会把月初评论的上月父节点截掉，也会丢失后续回复。

## 结构节点与分析样本分开

事件表和树重建保留同作者回复，也保留能提供父链信息的删除占位节点及平台标记。内容分析可按规则排除不可读文本；若排除结构节点，必须标记路径经过被排除节点，不能把孩子重新接根。

A连续回复自己可以形成很深的树，却没有账号往返。缺父、环、时间异常或未采到的楼中楼，也不能都写成平坦线程。报告n、d、w时同时给出可解析线程占比和异常原因；部分树的可见深度不能冒充完整最大深度。

## 数据上限与论文分母

本数据卡片说明：3月起原始`depth`没有大于5的记录。这个上限不是本项目重建深度5，更不能据此判断智能体只能对话五轮。

论文03的flat是在其有评论线程中没有超过顶层。论文04 v2图5则选取至少25条评论、并依作者规则筛为记录完整的讨论；§2.3、4.2还说明树分析限制在100条以下。两篇的比例不是同一总体，不能直接相减。作者的完整性筛选也不是本项目输入完整的保证。

## 选读：讨论树的深宽标度

标度分析考察d、w如何随n增长。论文04将d和w分别除以√n。若d近似常数、w随n增长，即使没有临界分支机制，两个归一化量也会呈反向关系；还须检查原始d(n)、w(n)。

比较时统一n是否含根、深度起点与筛选，报告各规模段的线程数和原始量。先保证树可重建，再讨论增长规律；本节不增加入门必做分析。
