# 回复树

**一句话**：回复树把帖子当作根，把每条评论接到它实际回复的父消息下面。

## 先看一个例子

帖子P下有评论B；C回复B；A回复C：

```text
P
└── B
    └── C
        └── A
```

按“帖子深度为0”的约定，B深度为1，C为2，A为3。

- **深度**：从帖子到最深评论的层数；
- **宽度**：某一层最多有多少条评论；
- **规模**：评论总数，不含帖子。

## 重建时先检查

父ID是否存在、父子是否属于同一帖子、父评论是否早于子评论、父链是否有环，都要检查。缺父或坏链不能自动接回帖子根，否则会制造假的平坦讨论。

整个月按评论时间截取，也可能把月初评论的父消息截掉；重建线程时应先取完整可观察线程，再按事件窗口筛选。

## 结构和内容不是一回事

回复很深，只说明嵌套结构深；不能直接说明作者轮流互动或内容有承接。一个账号连续回复自己，也能形成深树，却没有账号往返。

## 选读：讨论树的深宽标度

有时会比较深度 $d$、宽度 $w$ 与规模 $n$ 的关系，例如用 $\sqrt n$ 做归一化。归一化只是为了比较不同大小的树，不能替代报告原始的 $d$、$w$、$n$，也不能把不完整线程当成完整树。
