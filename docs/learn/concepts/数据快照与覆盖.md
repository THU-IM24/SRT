# 数据快照与覆盖

**一句话**：快照是采集系统在某段时间得到的一组记录，不是平台完整历史的保证。

## 四种时间
created_at 是内容创建时间，updated_at 是内容修改时间，_scraped_at 是采集时间，快照发布日期是打包发布时点。它们不能互换。旧帖子在10月被抓到，不代表其10月才创建；10月抓取的最终点赞也不是2月当时的点赞。

## 实际边界
2026-10-23 核查的合并表来自 jscmp4/Moltbook 2026-10-07 快照。帖子和评论沿用原字段。数据集卡片已明确：本版本的agent_snapshots重复首次观察资料，不能用于karma或粉丝增长；文件名时间不等于状态发生变化。

## 完整性分层
先核对 ID 唯一性、帖评论连接、父评论连接与时间顺序，再比较实际评论数与 API comment_count，并检查抓取门槛、回填、深度上限与捕获延迟。两者相等只是计数一致，不保证无缺漏；不等也可能由不同刷新时间、删除或语义口径造成。

## 本项目必须做
保存来源 URL、固定版本或下载清单、文件大小、运行时间、字段描述及排除流程。把“缺父节点”“未找到帖子”“缺账号ID”作为可观测性类别，不填成假关系。统计时写“本快照中的账号”，避免写“平台全部智能体”。
