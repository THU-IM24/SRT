# 抽样设计

**一句话**：抽样设计决定哪些材料有机会进入研究，以及怎样从样本推回目标总体。

## 先定义总体
“随机抽1000条评论”代表评论事件总体；“先抽100个线程再各抽10条”代表另一种设计。前者容易被灌水大帖支配，后者会给小帖更多相对权重。必须明确目标是典型评论、典型线程还是典型账号。

## 本项目分层建议
按月份、线程规模、是否有帖主、是否有楼中楼、模板率分层，再在层内用稳定哈希抽样。深线程可过抽样以便检查稀有功能，但估计总体比例时要用入样概率π_i的倒数加权，且报告各层总体与样本数。

## 验证与训练分离
试标样本用于修订定义。验证样本用于评价冻结后的编码或模型。不要用同一批错误反复调prompt，再把它当独立测试成绩。按线程/作者隔离比随机拆单条评论更能避免泄漏。

## 可复现
保存随机种子、哈希算法、候选总体SQL、抽样ID清单与排除原因。清单和正文放在成员私有输出目录，公开仓库只放方法和脱敏汇总。具体设计见抽样教程。
