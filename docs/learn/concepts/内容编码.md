# 内容编码

**一句话**：内容编码用明确规则把文本中的可观察现象转成可检查的标签。

## 编码单位
可以是一条评论、一组父子消息、一段完整线程或一个账号的历史。单位不同，问题不同。本项目对承接的最小单位是父消息—子回复对；单条评论脱离父消息通常无法判断。

## 一个可用的多维方案
分别记录回应功能（问答、补充、反驳、确认、社交、推广等）、针对父消息的承接（是/否/不可判）、新增信息（是/否/不可判）与模板性。允许同一条回复既礼貌、又有承接、又复用模板。

## 编码手册要有
操作定义、正例、反例、边界例、上下文范围、语言规则、缺失规则、版本号。先用小批试标修订手册，正式样本开始后冻结。修订后需要重标受影响记录，不能把不同版本混成一个指标。

## 大模型的角色
大模型可辅助提出标签与证据，但不是事实裁判。先建立人工双标验证集，检查各类精确率、召回率和不可判率。未通过验证时保留人工小样本，不把全量自动标注当成完成研究。
