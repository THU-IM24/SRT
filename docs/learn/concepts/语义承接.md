# 语义承接

语义承接指子回复具体处理父消息中的问题、证据、约束或主张。判断时需要同时看到父消息和子回复，不能只看回复是否“像一句好回答”。本研究用它把“存在回复边”推进到“内容是否对应”的可核对判断。它测量可见文本关系，不直接测量答案正确性、模型理解或任务完成。

## 可操作的最低要求

编码员应能指出父消息里的一个具体内容点，再指出子回复如何处理它。回答、补充、反驳、澄清、针对性确认都可承接；仅同主题、正面情绪、复用关键词或礼貌问候都不足以单独判“是”。

父消息（虚构）：“内存最多1GB，怎样统计评论？”

| 子回复（虚构） | 承接判断 | 需要单独记录什么 |
|---|---|---|
| “用DuckDB逐列扫描，并设置memory_limit。” | 是：提出处理内存约束的方法 | 方法是否有效不能只凭这句确认 |
| “AI社区数据分析很有趣！” | 否：没有处理具体问题 | 同属主题仍不等于承接 |
| “谢谢，我会按你说的1GB上限设置DuckDB。” | 是：针对性确认 | 不据此认定增加信息或已经执行 |
| “谢谢！” | 单凭此处不足以证明承接 | 可记社交功能；上下文充分时按手册判否 |
| 父消息被删除，且无可用上下文 | 不可判 | 记录缺失原因，不填否 |

错答和有依据的反驳也可能有承接。模板句如果确实处理具体内容，可同时记“承接是、模板是”；不要把模板性直接作为承接标签。

## 上下文和分母事先固定

顶层评论的父消息是帖子正文，楼中楼的父消息是父评论。需要祖先信息时，按教程统一最多补两层，并记录使用情况；语言无法理解、正文缺失或上下文仍不足记“不可判”。

父节点缺失通常在构造可解析候选总体时排除并报告；已进入样本但内容不足的保留“不可判”。两者都不能混成“无承接”。

人工承接率=承接数／可判对数；另报不可判比例。若共有100对，60是、20否、20不可判，可判率为80%，可判样本承接率为60/80=75%；全样本承接比例只知在60%—80%之间。非等概率抽样时这些计数均换成相应设计权重和。

## 真实父消息是否比同主题文本更有用

为同一子回复另配同月、同语言、相近长度与主题的其他父消息，隐藏真实／错配分组后盲审。错配对可能偶然承接，不能预先设为负标签。

分别计算两组人工承接率与差异，保存父内容点、子回复证据和独立标签。配对设计应保留同一子回复的关联，且不把错配对当成平台实际发生的互动。操作流程见[内容编码](编码一致性.md#内容编码单位标签与手册)。

## 论证关系

**选读**：复现论文03时再读。论证关系描述文本怎样支持、冲突或改述另一段主张，范围不等同于本页承接。

03的四类为Inference、Conflict、Rephrase、No relation。问答或针对性确认可能承接而没有论证关系；No relation只是该分类体系未识别到论证连接，不能直接解释为没有任何对话功能。

03使用从人类论辩材料训练的RoBERTa分类器。迁移到智能体模板、代码和多语言文本时，应先人工核查，尤其检查稀少类。原文comment–post分析与本项目包含楼中楼的实际父子对总体也不能混用。功能类型、承接、新增信息、模板性分别编码，不排成单一价值顺序。
