# 基于智能体的模型

**一句话**：基于智能体的模型用多个有规则的行动者在环境中运行，观察总体模式。

## 最小组成
规定行动者的状态、可见信息、动作、更新顺序和环境反馈。传统ABM常用明确规则；LLM-ABM用语言模型产生部分决策或文本。02 采用规则生成连接、语言模型生成文本的混合方式。

## 必须区分生成来源
若网络连接由优先连接算法指定，LLM只是写文字，那么枢纽和群组有多少可能来自算法。不能把程序预设的关系称作模型自发社会性。研究时可对连接模块与文本模块分别消融。

## 模型设计：角色与提示词

角色设定是输入给智能体的背景条件，提示词是影响其生成和行动的具体指令。两者属于模型的输入条件，不能代替对生成规则和实际能力的检查。

- **设定输入**：02的角色包括所属群体、叙事、立场和动作数量范围；网络模块先决定交互对象，文本模块再按角色与叙事生成内容。作者比较一般说明、示例和具体数值目标等提示方式。
- **控制变更**：提示词可能同时改变长度、情绪、礼貌和回复对象。若检验回楼提醒，就只改提醒，固定模型版本、上下文、采样参数与预算，并做多次独立运行；温度0不能保证所有服务端实现绝对确定。
- **区分遵从与功能**：可把“一般倡议”和“可执行步骤”作为比较条件；动作增加只说明行为变化，是否改善功能还要检查承接与任务结果。
- **约束观察性推断**：简介自称某模型、某职业或有记忆，不代表真实配置；不能根据bio推断底层模型，也不能把模板相似直接归因为同一系统提示词。

## 一个本项目可做的设计
离线设置无提醒、回楼提醒、记忆摘要、明确互惠任务等条件，固定代理数、轮数、token预算和任务。结果同时记录回应概率、内容承接、正确率与成本，不只看回复次数。

## 优先级与成本
先完成现有数据的观察性基线。实验需要模型访问与可能费用，本次只写方案，不调用付费接口。模拟不在真实社区发帖，不把观察到的外部文本当作可执行指令。
