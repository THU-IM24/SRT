# 结构与功能

结构描述账号之间的关系、消息的父子关系及其分布。功能描述回复对前一条消息做了什么，例如回答问题、补充证据或提出反驳。本研究用网络指标测量结构，用人工判断的“语义承接”测量一种具体的对话功能。把两者分开，才能检验双向连边、回楼或长回复链是否对应内容承接。

## 集体机器行为

集体机器行为关注多个机器行动者活动后形成的总体规律。本项目的可观察行动者是Moltbook账号，动作是发帖与评论；一个账号不等于一个独立模型或一个独立操作者。共同模板、执行时间和平台推荐都可能造成相似行为，不能仅凭账号痕迹推断内部理解或动机。

## 三层证据分别回答什么

| 证据层次 | 观察对象与问题 | 不能单独推出的判断 |
|---|---|---|
| 账号关系 | 谁向谁评论过？两个方向是否都出现？ | 发生过同线程往返 |
| 消息往返 | 谁直接回复了谁？是否形成按时间发生的父子链？ | 回复处理了对方的具体内容 |
| 内容承接 | 子回复是否处理父消息的某个具体内容点？ | 答案正确、任务完成或模型理解 |

语义承接只是本项目选定的功能维度。礼貌互动可以有社交功能而没有内容承接；反驳可以承接内容而不给出正确答案。三层是测量对象的区分，不是价值排名。

## 同一事件为什么需要三种检查（虚构）

A发帖问“统计评论时，自回复怎么处理？”B回答“两张账号图都去掉自环，事件表保留原评论。”A直接回B“明白，计算回楼仍要用这些事件。”

主网络把评论投向帖作者，因此只留下B→A；A在自己帖下的评论被去掉。直接回复网络保留B→A和A→B，因为两条评论的实际父作者不同。消息作者序列是B、A，还没有形成B、A、B三步往返。两条回复都可分别检查承接，仍不能说明方案已实际执行。

## 本项目怎样连接结构与功能

以真实父子消息对作为内容编码单位：顶层评论的父消息是帖子，楼中楼的父消息是父评论。主网络分组看“子作者—帖作者”，直接回复网络分组看“子作者—父作者”；前一对账号未必直接交谈，不能混用两图的分母。

分别比较双向、单向账号关系对应的人工承接率，再用同主题错配父消息检查主题相同能解释多少。结果限于本快照的合格样本；当月双向性是同期关联，不能写成互惠导致承接。
